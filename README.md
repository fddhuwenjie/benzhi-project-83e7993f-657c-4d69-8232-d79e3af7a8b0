# Sherd Proof 陶片拼合证据评议工作台

Sherd Proof 面向陶器整理员、考古绘图员和同行复核员，用可追溯状态机管理陶片拼合假说。系统把陶片基线、候选证据、结构化异议、版本化补证、独立复核与只读重建档案放在同一案件上下文内，避免未经充分论证的器形重建进入研究成果。

## 业务流程

1. 创建案件，登记遗址单元、器物类别和负责人。
2. 登记至少两件资料完整的陶片，冻结后基线不可增删。
3. 为基线陶片建立候选拼合，填写边缘、胎土、纹饰、尺度和图像五类证据；完整度达到 100% 后公开评议。
4. 团队成员对具体候选证据项提出异议。受质疑项被锁定，必须通过版本化补证、维持说明或撤回候选逐项关闭。
5. 所有异议关闭且仍有有效候选时提交复核。未参与建档和候选编辑的复核员可通过，或只开放指定证据项定向退回。
6. 复核通过后生成规范化档案、只追加事件摘要链头和 SHA-256 校验值，并将案件冻结为只读状态。

## 构建与运行

```bash
go build ./cmd/server
go run ./cmd/server -addr=127.0.0.1:19081
```

默认监听 `127.0.0.1:19081`，数据写入 `data/sherd-proof.db`。可用 `-data` 指定 SQLite 文件。设置合法的 `PORT` 端口号时，未显式传入 `-addr` 会监听 `127.0.0.1:<PORT>`。打开 `http://127.0.0.1:19081/` 即可使用工作台。

## 测试与自检

```bash
go test ./...
go run ./cmd/server -selftest -addr=127.0.0.1:19081
```

`-selftest` 使用临时 SQLite 数据库和真实回环 HTTP 监听，完整执行从建档到档案校验的正常流程，完成后自行关闭并退出。

## 数据完整性

每个写命令都要求 `expected_revision`，陈旧页面不能覆盖新修订；`request_id` 与请求指纹用于持久化幂等重放。审计事件使用前一事件摘要串联 SHA-256，定稿档案保存规范化载荷及定稿时事件链头，验证端点会重新计算两者以检测篡改。
